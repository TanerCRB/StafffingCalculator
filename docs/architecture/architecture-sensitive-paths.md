# Architecture-sensitive paths

Read by the task command's fast lane (`.claude/commands/task.md`, "Fast lane: when the Architect
is skipped"): a task touching any path below always goes through the Architect. A path missing
from this list is a path the fast lane will wave through — when in doubt, add it. Keep this file
current when a new sensitive area is created; the Architect maintains it, not just consults it.

| Path (glob) | Governing decisions | Why it's sensitive |
|---|---|---|
| `backend/migrations/**` | ADR-0001, ADR-0008 | Schema change; expand/deploy/contract, effective-date overlap rules |
| `backend/app/core/money.py`, `frontend/src/lib/money.ts` | ADR-0002, ADR-0006 | The only place `Decimal`/rounding and currency conversion are allowed to happen |
| `backend/app/models/**` | ADR-0003, ADR-0004, ADR-0007, ADR-0009, ADR-0013, ADR-0016 | Calculation versioning, concurrent-edit rules, write-from-UI contract — `ADR-0003` (commercial rule shape, `commercial_terms`/`tm_terms`/`story_points_terms`) and `ADR-0016` (`scenario_delivery_segment`) named explicitly, not only implied by ADR-0004's grouping — row widened 2026-09-25, impact map SC-4-05. `ADR-0013` named explicitly: `staffing_position.cost_basis`/`fixed_amount` are personnel-cost columns living directly on this table (not a grandchild), governed by ADR-0013's F-07 cost-basis dispatch, not only implied by ADR-0004's grouping — row widened 2026-09-25, impact map SC-5-03 |
| `backend/app/api/**`, `frontend/src/api/contracts/**` | ADR-0003, ADR-0005, ADR-0009, ADR-0017 | Access model / permission pipeline, API surface contract. `ADR-0003` named explicitly: the per-model response shape (`assumptions_used`, `expected_state`/`expected_amount`, `category_revenues`, `outcome_terms`, `profitability_state`) and its closed value sets are commercial-model decisions, not only API-surface ones — row widened 2026-09-25, impact map SC-4-07. `ADR-0017` named explicitly: any endpoint returning a list adopts the shared `limit`/`offset`/`total` pagination pattern, its ordering/tie-break rule and the scope-before-parameter-validation precedence on scoped resources — row widened 2026-09-26, impact map SC-3-05 |
| `frontend/src/api/client.ts` | ADR-0003, ADR-0009, ADR-0010 | The single network entry point for every read and write — the write-from-UI contract (timeout budget, per-endpoint no-refetch narrowing, refusal shape) and the shape-check-before-render boundary live here, not in a screen component; a task adding a write function here extends a decision even when it adds no new contract type (impact map SC-6-03, 2026-09-24). `ADR-0003` named explicitly: the closed value sets of the shape check (`model_type`, `rate_source`, `hours_source`, `vendor_axis`, `expected_state`, `profitability_state`) and their pairing with `model_type` are a block-4 common element — every commercial-model task adds only its own model's values (ADR-0003, addendum 2026-09-25 SC-4-07, pt 4–5) — row widened 2026-09-25, impact map SC-4-07 |
| `backend/app/domain/**` | ADR-0002, ADR-0003, ADR-0004, ADR-0005, ADR-0013, ADR-0014, ADR-0015 | Revenue/personnel-cost/additional-cost calculation rules; code combining amounts from more than one of these (e.g. profit/margin/markup, F-10) crosses money handling (ADR-0002), the revenue model (ADR-0003), snapshot-vs-live reading (ADR-0004) and the personnel-cost gate (ADR-0005) at once — row widened 2026-09-24, impact map SC-7-01. `ADR-0015` named explicitly: any change to `base_personnel_cost`/`paid_absence_cost`'s input shape (e.g. a new cost component, SC-5-02) is a change to the shared rate structure the what-if substitution (`app.data.scenario_what_if`) depends on being able to reuse "as a fourth caller" without its own arithmetic — row widened 2026-09-25, impact map SC-5-02 |
| `backend/app/data/**` | ADR-0001, ADR-0003, ADR-0004, ADR-0005, ADR-0007, ADR-0013, ADR-0015, ADR-0016 | The scope-guardian layer (`project_for_caller`/`project_reads`), the write-guard layer for `approved` scenarios (`scenario_guard` evaluated in the same statement as the write, `SCENARIO_CHILD_COPIERS`) and snapshot writer/readers, and the revenue/cost-window predicates (`commercial_terms`, `personnel_cost`, `rate_windows`) live here — one level below `app/models/**` (schema) and above `app/domain/**` (formulas); a new append-only or history-reading module composes with these guards and was previously not named in this table — row added 2026-09-25, impact map SC-8-01. `ADR-0003`/`ADR-0016` named explicitly: `app.data.commercial_terms` and `app.data.scenario_delivery_segment` are exactly where a `scope_ref` composite foreign key and the `SCENARIO_CHILD_COPIERS` ordering between the two live — row widened 2026-09-25, impact map SC-4-05. `ADR-0007` named explicitly: per-model revenue dispatch, `rate_source` comparisons (the `/results` race guard) and concurrency-marker checks live here too — a change can break immutability, isolation or reproducibility without touching `backend/app/models/**` or `backend/migrations/**` — row widened 2026-09-25, impact map SC-4-03. `ADR-0015` named explicitly: `app.data.scenario_what_if` is the one module reusing `_worked_months`/`base_personnel_cost`/`paid_absence_cost` on a substituted, never-persisted rate structure — a new cost component (SC-5-02) that these functions consume changes what that module must substitute too — row widened 2026-09-25, impact map SC-5-02 (merged with the SC-4-03 widening after the merge with `main`) |
| any new/changed public API endpoint, response field or event | ADR-0005, ADR-0009, ADR-0017 | Public contract surface. `ADR-0017` named explicitly for any new list endpoint or new pagination fields — row widened 2026-09-26, impact map SC-3-05 |
| `frontend/src/features/projects/**` (screens/sections rendering `RESULTS_READ` or personnel-cost-gated data — revenue, personnel cost and additional cost shown together — and the commercial-terms rule section rendering `COMMERCIAL_READ` data: rule parameters, per-model revenue, guaranteed/expected revenue, outcome categories; also a section/screen rendering `STAFFING_READ` data — staffing positions, their monthly allocations and planned absences) | ADR-0002, ADR-0003, ADR-0005, ADR-0010 | Frontend render of the personnel-cost gate's `null` next to a source's own named non-computable state; a wrong precedence, a shared sentinel across sources, or a currency inferred from outside the payload misstates a gated figure without touching `frontend/src/api/contracts/**` or `frontend/src/lib/money.ts` — row added 2026-09-24, impact map SC-7-02. Widened 2026-09-25, impact map SC-4-07: render and labels chosen by `model_type`, never by `rate_source`; guaranteed vs expected revenue shown as two labelled amounts, never one standing in for the other; rule parameters "as stored" (`null` ≠ `0`); the `currency_mismatch` section status line independent of the gate while gated fields stay "niedostępne" (ADR-0003 and ADR-0005, addenda 2026-09-25 SC-4-07). Widened 2026-09-26, impact map SC-3-04: `STAFFING_READ` data carries no rate/cost/currency and is deliberately not personnel-cost-gated (ADR-0005, addendum SC-3-01 point 5) — but rendering it is exactly the trigger ADR-0005's addenda SC-3-02 point 11 and SC-3-03 point 7 named and left dormant ("first task dependent on distinguishing `headcount = 1` from `headcount > 1` in the API response must name the pseudonymization degradation and decide on a countermeasure"): a screen showing a position's catalogue dimension tuple beside its absences and leave-budget figures is the first place a human, not just a backend test, sees the identification this row's headcount makes possible. A future task in this path that renders staffing data without addressing that reopened question is a candidate for the same gate, whether or not it touches `money.ts`/`client.ts` in the same change. If the screen instead lives in a new top-level feature directory (not under `projects/**`), that directory needs its own row here before gate 3 — flagged, not yet added, pending the actual file location (impact map SC-3-04) |
| any new or upgraded dependency (package manifest, lock file) | — | Supply-chain surface, see `security-auditor.md` |
