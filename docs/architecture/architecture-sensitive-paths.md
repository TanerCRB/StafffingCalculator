# Architecture-sensitive paths

Read by the task command's fast lane (`.claude/commands/task.md`, "Fast lane: when the Architect
is skipped"): a task touching any path below always goes through the Architect. A path missing
from this list is a path the fast lane will wave through — when in doubt, add it. Keep this file
current when a new sensitive area is created; the Architect maintains it, not just consults it.

| Path (glob) | Governing decisions | Why it's sensitive |

| any new/changed public API endpoint, response field or event | ADR-0005, ADR-0009, ADR-0017 | Public contract surface. `ADR-0017` named explicitly for any new list endpoint or new pagination fields — row widened 2026-09-26, impact map SC-3-05 |
| `frontend/src/features/projects/**` (screens/sections rendering `RESULTS_READ` or personnel-cost-gated data — revenue, personnel cost and additional cost shown together — and the commercial-terms rule section rendering `COMMERCIAL_READ` data: rule parameters, per-model revenue, guaranteed/expected revenue, outcome categories; also a section/screen rendering `STAFFING_READ` data — staffing positions, their monthly allocations and planned absences) | ADR-0002, ADR-0003, ADR-0005, ADR-0010 | Frontend render of the personnel-cost gate's `null` next to a source's own named non-computable state; a wrong precedence, a shared sentinel across sources, or a currency inferred from outside the payload misstates a gated figure without touching `frontend/src/api/contracts/**` or `frontend/src/lib/money.ts` — row added 2026-09-24, impact map SC-7-02. Widened 2026-09-25, impact map SC-4-07: render and labels chosen by `model_type`, never by `rate_source`; guaranteed vs expected revenue shown as two labelled amounts, never one standing in for the other; rule parameters "as stored" (`null` ≠ `0`); the `currency_mismatch` section status line independent of the gate while gated fields stay "niedostępne" (ADR-0003 and ADR-0005, addenda 2026-09-25 SC-4-07). Widened 2026-09-26, impact map SC-3-04: `STAFFING_READ` data carries no rate/cost/currency and is deliberately not personnel-cost-gated (ADR-0005, addendum SC-3-01 point 5) — but rendering it is exactly the trigger ADR-0005's addenda SC-3-02 point 11 and SC-3-03 point 7 named and left dormant ("first task dependent on distinguishing `headcount = 1` from `headcount > 1` in the API response must name the pseudonymization degradation and decide on a countermeasure"): a screen showing a position's catalogue dimension tuple beside its absences and leave-budget figures is the first place a human, not just a backend test, sees the identification this row's headcount makes possible. A future task in this path that renders staffing data without addressing that reopened question is a candidate for the same gate, whether or not it touches `money.ts`/`client.ts` in the same change. If the screen instead lives in a new top-level feature directory (not under `projects/**`), that directory needs its own row here before gate 3 — flagged, not yet added, pending the actual file location (impact map SC-3-04). Widened 2026-09-27, impact map SC-7-04: the same open question recurs for "Compare scenarios" (`RAIL_WORKSPACE` planned entry, F-09/Issue #11, backend endpoint delivered by SC-6-02) — rendering N `RESULTS_READ`/personnel-cost-gated rows side by side is exactly this row's trigger repeated at N>1, and whether that render lands under `projects/**` or a new top-level directory depends on gate 1's resolution of the navigation/scenario-selection mechanism repeatedly deferred as decision D-2 (SC-4-06, SC-7-02, SC-3-04). Flagged, not yet added, pending that decision and the actual file location |
